# RC26 釣果のエリア編集

## 調査と基点

PR #25のマージをGitHub APIで確認し、最新main `b1514b896f6343243268f52691b7f2bd6939d191`から`feature/rc26-catch-area-edit`を作成。

既存スキーマはCatchRecordの`facilityId`・`zoneId`・`locationSnapshot`、FishingTripの`facilityId`・`currentZoneId`。施設／エリアは`official:`または`user:`のstable IDを持ち、エリアの`facilityId`で所属を検証する。

CatchModalには既に共通のlocation slotがあり、新規登録・編集ともFacilityPickerが接続されていた。ただし、釣行の施設IDがなければ欄全体が非表示になり、未解決の既存エリアIDは候補読み込みをエラーにしていた。実機の個別レコードは参照しておらず、その実機事象の原因を断定したものではない。

## 変更内容

- 新規登録・編集とも共通FacilityPickerを常に表示し、「釣り場内のエリア」と明記する。既存のレンジ（水深）の選択機能・候補は変更しない。
- 釣行facilityIdに属する正式／ユーザー登録エリアだけを既存のsortOrder順で表示する。別施設の候補は混ぜない。未設定も選べる。
- 施設IDなしは未設定欄と案内を表示し、施設名による推測紐付けをしない。エリア未登録でも他の釣果編集を妨げない。
- 未解決の既存エリアIDは元の名称・IDを保持する選択肢として示し、通常候補へ混ぜない。変更しなければ元のIDとsnapshotを保持する。有効な別エリアへの変更・解除は明示操作で行う。
- IDがなく旧エリア名だけあるsnapshotも、名称を保持する旨と明示解除ボタンを表示する。解除時も元の施設名は残す。
- 選択はフォーム内の下書きのみ。釣果の保存を押すまでDBを変更せず、キャンセルは元の値を維持する。既存のユーザー施設／エリア追加操作は別の明示登録として維持する。
- 編集時にエリアへ触れていなければ場所の再解決を行わない。同じIDへ戻した場合も履歴を無用に更新しない。変更時には既存のトランザクション内で施設・エリア所属・現在エリアの整合性を検証する。
- 同じ施設のエリアだけ変えた場合、履歴の施設名は保持し、新しいエリア名を保存する。釣行の現在エリアは変更しない。
- 釣果ID・tripId・時刻・ルアー・水深・速度・アクション・魚種・サイズ・メモ・タックルを保持する。旧形式のresultType未設定や空文字も、未変更時には正規化し直さない。
- 編集開始時のレコードを保存トランザクションで照合し、別画面で変更されていれば保存を拒否する。保存障害時はロールバックし、エラーを表示して入力を保持する。
- 保存後は既存loadCatchesを再実行するため、タイムライン・エリア別表示中件数・棒グラフへ反応的に反映する。ページ全体のリロードは不要。総釣果・平均ペース・気象・イベントは変更しない。

## 操作・iPhone実機確認

検証用originと合成記録を使い、本番バックアップの復元や実機IndexedDBの削除はしない。

1. Safariまたはホーム画面PWAで釣行詳細を開き、釣果履歴の「編集」を押す。終了済み釣行とバラシも対象。
2. モーダル上部の「釣り場内のエリア」を選び、「保存する」を押す。未設定→設定、A→B、設定→未設定を確認。
3. 再度開いて値を確認し、別の値へ変更してキャンセル。元の値が残ることを確認。
4. タイムラインのエリアを選び、表示中件数・キャッチ／バラシマーカー・時間帯別棒の合計が更新され、全体の総釣果・平均が変わらないことを確認。未設定の含有／除外も確認。
5. 長い施設・エリア名でもモーダル内に収まり、縦スクロールで保存・キャンセルへ届くことを確認。共通Pickerの既存の幅制限と44px以上の操作方式を維持する。
6. PWAの圏外準備完了後に機内モードで編集・保存し、完全終了・再起動して保持を確認。検証用データだけでバックアップv7をエクスポート・復元し、エリアとsnapshotの保持を確認。

## 互換性・制約

DB v8・19テーブル、気象ありバックアップv7、旧v1〜v6入力、正式施設50件／73エリア、気象・地点再利用・PWA更新方式を維持する。スキーマ・配布ゲート・依存関係・API通信を変更せず、未承認座標を取り込まない。

施設IDなしの釣行へ施設を後から紐付ける機能は本PRに含めない。その場合は未設定のまま編集でき、既存の名称・場所履歴を推測で変更しない。施設参照自体や現在エリアが壊れている場合、新しい場所の保存は既存の整合性検証で拒否する。未変更の履歴は保持する。

実機Safari／ホーム画面PWAは未確認で、モバイル自動試験はiPhoneサイズのChromium。既存の500kB超bundle警告が残る。Draft PRで終了し、マージ・自動マージ・mainへの直接push・デプロイを行わない。
