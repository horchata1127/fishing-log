# RC23 実装報告

実施日: 2026-10-12。ブランチは `feature/rc23-lost-fish`、基点HEADはRC22のPR #17マージ済み `5579a27`。実装指示書は既存の `RC23_LOST_FISH_SPEC.md`。外部のRC20仕様書は既存ID・参照・未追跡ファイルの保護要件を参考にした。

## データ構造と互換性

案Aを採用した。既存 `catches` に `resultType?: 'catch' | 'lost'`、`lostDistance?: 'offshore' | 'near' | 'landing'` を追加する。旧レコードの結果未指定は読み取り時だけキャッチとして扱う。既存全件の更新・補完・再採番を行わない。既存ストア・索引の変更が不要なためDB v7を維持し、マイグレーションを追加しない。

バラシは3区分の距離を必須とし、不正な結果・距離は保存とバックアップ復元で拒否する。キャッチへ切り替えて保存した場合は距離を消す。魚種・サイズ・ルアーは任意。ルアー未選択は従来と同じ手入力空欄扱いで保存できる。モーダルの結果切替では入力したルアー・魚種・サイズ・距離等を保持する。

バックアップは既存の形式判定を維持する。新テーブルや必須フィールドを増やしていないため、形式versionを一律変更しない。RC22相当の合成バックアップとRC23記録入りバックアップはいずれもv5であり、既存施設情報がある環境は従来どおりv6となる。旧v1〜v6互換を既存テストで維持し、新任意フィールドは書き出し・復元で保持する。

## 動作と保護

登録・編集画面でキャッチ／バラシを選択できる。初期値はキャッチ。バラシ時は距離未選択で通常保存と「前回と同じ」の両方を無効にし、理由を表示する。保存後に結果別の完了表示を行う。保存中ガードとモーダルinertにより二重操作を防止する。

保存後の集計・候補読み込みが完了するまで釣行画面の操作ボタンも無効にする。画面の一部だけ先に更新されても、直後の編集操作が無言で失われないようにした。

釣行画面ではキャッチ数、バラシ数、距離別バラシ数を分ける。魚種集計にはキャッチだけを含める。履歴は結果・時刻・ルアー・距離を表示し、旧キャッチの匹目表示も維持する。ルアー別比較を釣行内に追加し、My Luresではキャッチ／バラシを並記する。釣行削除の確認も両件数を区別する。

記録の追加・編集・削除はユーザー操作に限る。追加・編集は既存の単一Dexieトランザクションで参照・スナップショットを検証する。削除は対象IDと親釣行を確認する。途中失敗はロールバックする。既存記録や所有ルアーを起動時に変更しない。

2026-10-12の仕様修正に従い、従来のカタログ使用時の自動所有登録を維持する。キャッチ・バラシとも、カタログのモデル・カラー・親メーカーを検証してから、同じ色の既存実所有個体を再利用する。候補が複数あれば直近使用個体、なければID順で選択する。実所有候補がなければ `ownershipStatus: 'owned'` の個体を1件追加し、記録と同一トランザクションで保存する。並行保存でも二重作成せず、途中失敗時は所有追加もロールバックする。手入力だけでは名前がカタログと一致しても所有を自動登録しない。編集・削除・結果切替で所有を自動削除しない。

未確認・placeholder・使用停止個体は従来の実所有判定を維持し、自動で実所有へ昇格させない。RC22までの既存行・ID・登録状態を変更せず、必要な新しい実所有個体だけを追加する。「前回と同じ」と最近使用は所有IDのないカタログ参照にも対応する。所有数は常に固定する要件から、既存行の保持と不足個体だけの追加を要求する仕様へ変更した。

カタログのRC19〜RC22原本・追加処理には変更を加えない。魚種・タックル・釣り場の旧スナップショット方針を維持する。過去のバラシ約2回を推測登録しない。
