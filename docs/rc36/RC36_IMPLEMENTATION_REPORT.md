作成日：2026-11-03（日本時間）。ユーザー本人・ようこちゃんのレビュー用。実iPhoneでの確認とレビューは未完了。

## A. 実装概要

釣行詳細にサマリーを追加し、釣行日・釣り場・天気・経過時間・キャッチ・バラシ・釣果時速・反応時速・MVP・ルアー別表を表示する。MVPは名前・カラー・暫定フラグをユーザーが保存でき、自動候補より優先する。

HTMLの専用カードから1080×1350pxのPNGを生成し、同じPNGをプレビュー・保存・ファイル共有に使用する。ルアー表の全件画像、項目選択、投稿文コピー、X投稿画面を開くリンクも追加した。

時間帯別グラフの画像への埋め込みは未実装（任意項目）。既存画面のグラフは維持。SNS APIによる直接投稿、投稿成功の保証、相関分析、高度な編集、PDF、動画は対象外。長文・多件数でも1枚の縦長カードを保つため、サマリー表は上位8件＋残りの集計、全件表は14件ずつのページに分ける。本文は必要な場合に限りフッターの内側に収まるよう縮小する。

## C. サマリー・画像出力仕様

### 集計とMVP

- 対象釣行IDに属する記録だけを使用する。`resultType` 未設定の旧記録は既存仕様どおりキャッチ扱い。
- 分母は保存された有効な開始〜終了の実経過時間。釣行中、未設定、0、逆転、不正日時の場合は時速を表示しない。現在時刻やグラフ表示範囲から補わない。
- 釣果時速＝キャッチ数÷時間、反応時速＝（キャッチ＋バラシ）÷時間。実時間で計算し、どちらも `toFixed(1)` で小数1桁表示。
- ゼロ釣果で有効期間がある場合は0.0。1分未満の有効な期間は「1分未満」と表示し、時速計算には秒以下も含む実時間を使う。
- ルアーの識別はRC35と同じく、カラーのvariantId、所有ID、手入力の名前＋カラーと保存済み配色で行う。画面では保存名・カラーを表示。画像では長い名前・カラーに「…」を付ける。
- 自動MVP候補はキャッチ数、同数ならバラシ数、名称・識別キーの順。キャッチがない場合は候補なし。ユーザー指定があれば常に優先し、「暫定」を別途指定できる。
- 天気は既存の `trip.weather` を優先。空欄なら同じ釣行の最新の観測済み空模様を「観測」と表示する。未記録は推測しない。

### PNGと共有

- `html2canvas` を遅延読込し、端末のフォントとシンプルなHTML/CSSで描画する。外部画像・Webフォントは使わない。PWA precacheには画像生成用JSも含める。
- PNGは1080×1350px（約1.46MP）、canvas倍率1。上部に釣り場・日付・天気・時間、件数・時速、MVP、ルアー別表、任意のメモ・気象要約、下部フッターを配置する。
- サマリーは上位8件。超過分は件数・キャッチ・バラシを明記し、全件はルアー表専用画像から出力できる。ルアー表は14件／ページ。37件の場合は14・14・9件の3画像となる。
- MVP・表・メモ・気象要約の画像への表示を切替可能。メモと気象要約は初期OFF。これらの選択は一時的な画面設定で、DBには保存しない。
- 生成済みBlobをそのままプレビューし、同じFileを保存・共有へ渡す。設定・ページ・記録の変更後は古い画像を無効化する。
- 共有は生成完了後の別クリックから実行し、ファイル共有対応を `canShare({ files })` で確認する。非対応・共有エラーはPNG保存へ進み、文面コピーと画像添付を案内する。ユーザーの共有キャンセルでは自動保存・成功表示を行わない。
- 共有シートへの引き渡しとSNS投稿完了を区別する。Xリンクは文面のみを渡す。画像は共有先またはXの投稿画面でユーザーが添付・投稿する。

## D. UI・操作手順

1. 釣行詳細の「釣行サマリー」で数値・MVPを確認する。「ルアー別釣果表」を開くと全件を閲覧できる。
2. 「MVPを指定・編集」で記録済みルアーを選ぶか名前・カラーを入力し、「MVPを保存」。指定解除で自動候補へ戻す。終了後でも編集できる。
3. 「サマリー画像・共有」を開き、画像の種類・必要な項目を選ぶ。「画像プレビューを作成」でPNGを生成する。
4. プレビューを確認して「画像で保存」または「共有」。iPhoneでは画像の長押し保存も代替手段になる。
5. 「ルアー別釣果表（全件）」の場合はページを選び、ページごとに生成・保存する。
6. 必要に応じて投稿文をコピー、またはXの投稿画面を開き、画像を添付する。コピーAPIが使えない場合も文面欄から選択・コピーできる。

## F. データ保護・既存機能への影響

Dexieスキーマはv10のままで、新テーブル・マイグレーション・初期化は不要。追加フィールドは任意の `trips.summaryMvp` のみ。保存は対象釣行のMVPだけを更新し、競合時は上書きしない。

MVPが存在するバックアップのみv11で出力する。MVPがない場合のv2〜10自動選択とv1〜10の読込を維持。v11でMVP・RC35の気象ログ・メモを含む復元を2回行い、履歴以外の既存全テーブルが一致すること、破損入力が書込前に拒否されることを確認した。復元履歴が増えるのは既存仕様。

画像生成・項目設定・共有はDBを書き換えないことを画面テストで比較した。釣果登録、マスター・カラー・所有更新、RC35メモ・気象ログ保存やタイムラインのロジックは変更していない。既存の集計・釣行削除・RC34履歴／適用画面を回帰確認した。圏外再起動後の初回PNG生成、MVP保存・再起動・バックアップも成功した。

## G. 残課題・レビュー事項

- 実iPhoneで日本語表示、写真アプリへの保存、画像長押し、共有シート、Xへの画像添付、ホーム画面PWA更新・圏外起動を確認する。投稿成功は保証しない。
- 画像は端末フォントで描画するため、OS間で字形や改行位置が異なる場合がある。長文は抜粋・縮小される。元の記録は変更しない。
- 全件表はページごとに画像生成・保存する。複数画像の一括共有は未実装。
- 時間帯別グラフの画像への埋め込み、追加テンプレート・高度な編集・SNS API直接投稿は今後の拡張。既存の画面グラフはそのまま利用できる。
- 本番ビルドは成功するが、メインJSの500kB超チャンク警告がある。html2canvasは別の遅延読込チャンク（約199kB、gzip約47kB）。
- レビュー対象は時速の自然さ、自動候補／指定MVPの区別、8件を超えた際の表の案内、画像の文字サイズ、iPhoneの保存・共有操作。
