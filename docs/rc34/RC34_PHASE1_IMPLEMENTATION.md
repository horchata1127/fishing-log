## 実装結果

RC19〜RC33のカタログ対象を累積マニフェストへ統合し、入力スナップショットから追加・保持・保留を計画する共通planner、およびIndexedDBの読み取り専用プレビューを追加した。

今回はPhase 1のみ。DBはv9・21ストア、バックアップは既存v1〜v8のまま。DB v10／バックアップv9、実行履歴、統一画面、旧RC別ボタンの廃止、実際の共通applyは次Phaseで実装する。承認済みの方向性は変更していない。

アプリの既存コード・画面・RC別データ・テストを変更せず、新規ファイルのみ追加した。実端末への接続・適用・バックアップ復元は行っていない。既存の未追跡資料・予備ファイルも変更していない。

RC19の旧表示名は別名と元ソースに残し、未登録色の表示にはRC20の公式表記を使用する。RC31/33の共有色はRC31の表記・属性・照合規則を保持し、RC33の購入指定・配色候補だけを付加する。新しいRC間重複は明示的な対応付けなしではマニフェスト生成時にエラーになる。階層キー、モデル・カラーの重複、マージ時の属性・名称・JAN矛盾も検査する。

RC23〜27・RC29・RC32は独立したカタログ追加パックがない。これらの実装・データ・開発資料はそのまま保持する。RC32の全件名称推定を共通plannerから自動実行することはない。

## 共通plannerの仕様

`planLureMaster(snapshot, options?, manifest?)` は入力・既存データを変更せず、次を返す。

- メーカー・シリーズ・モデル・カラーの追加計画と、追加／保持／保留の色別結果。
- 元RCのカラー原本、出典URL・階層、JAN、限定区分、保留理由、既存ID。
- RC33の所有追加／保持、公式画像配色／名称推定／未確認／既存配色保持の予定。
- マニフェスト・照合規則版・名称推定器版・所有オプション・関係ストアの全内容を含む比較トークン。

追加計画の負のIDはメモリ内だけの親子参照である。固定の製品IDや実DBのIDとして使用しない。次PhaseのapplyがDB採番して対応付ける。既存IDを変更する操作やupdate/delete操作は計画に含めない。

照合は元RCごとの規則を区別する。メーカーの表記揺れ、親階層、別シリーズの同名モデル、重量・全長・タイプ、モデル内コード、名称・明示別名、限定区分、JANを検査する。承認済みの自然キー方式に従い、RC21/22のメーカーID62/71への依存は共通plannerには持ち込まない。商品検証・モデル作成許可・重量必須等は維持する。

曖昧候補や属性・コード・JAN・配色参照の競合では、対象モデルの仮計画を捨て、モデル全色を保留する。異なる商品が同じ既存モデルIDを指す場合は双方を保留する。元からある重複を削除・自動統合しない。

内部の仮想状態により、複数対象の共通親を一度だけ計画する。後のパックが作成を許可されたメーカーを供給する場合は、先の保留対象を仮想状態で再照合し、一回のプレビュー内で依存関係を解決する。確認用のDB仮登録は行わない。

`previewLureMaster(options?)` は6ストア（マスター4表・myLures・lureVisualProfiles）を同じ読み取り専用トランザクションで取得する。DBへの書き込み・復元・起動時適用・外部通信は行わない。

## RC33の所有・配色保護

所有オプション `includePurchases` は初期OFF。ONの場合のみ、購入指定11個の不足分を追加予定として返す。同じvariantIdの既存所有は非アクティブ・未確認でも保持し、状態を昇格させない。今回は予定表示までで、所有への書き込みはない。

公式画像29件・名称推定12件・未確認20件を維持する。配色予定には可視面の値、画像／出典URL、推定器版・根拠・確信度を含める。未確認色には配色を捏造しない。既存プロフィールは手動編集・確認済み・推定済みをすべて保持する。参照解除済みや自然キーとvariantIdが一致しないプロフィールは保留し、再リンクや二重追加をしない。

GA-24SはRC31と統合したモデル全体として計画するため、その共有色に配色参照の競合があればモデル全16色の計画を保留する。既存RC33単独処理より保留範囲が広いが、部分適用による不整合を防ぐ方針である。

仮配色・釣果snapshot・所有・釣行・釣果の変更操作は提供しない。

## 残課題

- DB v10、実行履歴の開始・成功・失敗・中断、復元文脈、バックアップv9と履歴マージを実装する。
- 共通applyで適用直前の再照合・DB採番・親ID対応付け・履歴成功確定を原子的に行う。今回の追加計画をそのまま負ID付きでDBに挿入しない。
- UIを統一入口と履歴画面へ接続し、RC別ボタンを廃止する。旧JSON互換入口を分離し、開発履歴を圏外閲覧できる形で同梱する。
- 現在の比較トークンはデータ内容を直接含む文字列で、内容ハッシュではない。次Phaseで永続履歴用のハッシュと版識別を接続し、端末メモリ・表示負荷を計測する。
- 新plannerは現行画面からまだ呼ばないため、製品バンドルでは未使用コードとして除外される。新しい更新フローのE2E・圏外適用・SW更新延期・Safari実機検証はUI／apply接続後に実施する。今回はブラウザE2E・offline試験を実行していない。
- 元データの未確認SSS11色、別配列の保留注記27件、配色未確認20件は維持している。新たな製品調査や保留解除はしていない。

コミット・push・PR作成・公開・実端末更新は行っていない。
