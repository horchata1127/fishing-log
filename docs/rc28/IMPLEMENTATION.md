## 追加専用の取り込み

ホームの「RC28の追加予定を確認」で読み取り専用照合を行い、端末ごとの追加・保持・保留と出典を表示する。確認結果をCSVで保存できる。「RC28の確認済みカタログを追加」で不足分だけを追加する。

メーカー、シリーズ、モデル、カラーの4テーブルだけをトランザクション対象にする。既存行へのput/update/delete/clearは使わない。マイルアー、釣果、釣行、タックル、魚種、施設、気象データは変更しない。カタログ適用時に所有登録しない。

親スコープと明示的エイリアスで照合する。重量・全長・タイプ不一致、候補重複、別シリーズに同名モデル、JAN競合、色名・色番号・限定区分の矛盾はモデル全体を保留する。色番号だけで異なる色を同一視しない。RC/1091/有頂天で同じ番号が使われるため番号は限定区分の中で比較する。既存色の区分が不明で番号が競合した場合も保留する。

適用トランザクション内で再照合し、事前確認時の4テーブル全内容と比較する。別タブや開発中のカタログ変更があれば再確認を求める。所有・釣果だけが増えた場合はそれらに触れず追加を続行できる。再実行は0件追加、途中の書き込み失敗は全追加をロールバックする。

catalogEvidenceにRC28、区分、メーカー/販売店URL、JAN、原名、色番号、重量、全長、浮力、ラトル、製品出典を保存する。型を拡張しただけでDexieのstoresやバージョンは変更していない。既存バックアップの未知フィールド保持によりRC28メタデータも往復できる。

## 再生成・再調査

`python scripts/prepare-rc28-catalog.py` はrequests/beautifulsoup4を用いた手動資料作成用スクリプト。アプリ実行時には通信しない。取得HTML/Shopify JSONはgitignoredな`node_modules/.cache/rc28`に置く。資料更新時はキャッシュを明示的に入れ替えて差分をレビューする。全重量×全色の直積生成はしない。

`node scripts/audit-rc28-backup.mjs <ローカルのバックアップパス>` は現行バリデータと純粋なカタログ照合関数を使う。バックアップをDBへロードせず、公開カタログ差分と集計だけを書き出す。履歴や所有データをフィクスチャ化しない。
