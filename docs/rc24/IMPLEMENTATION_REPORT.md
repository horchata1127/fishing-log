# RC24 アクション拡張・アクションの長さ

`RC24_CODEX_IMPLEMENTATION_INSTRUCTIONS.md` を全文確認し、PR #20がマージ済みであることをGitHub APIとGit履歴で確認した。最新 `origin/main` `6e18747c99eb0f08591ee309e50469bfb085fd1a` を起点に `feature/rc24-action-expansion` を作成。開始時に追跡ファイル差分なし。既存未追跡11ファイルはハッシュを記録して保護した。

## データ契約と保存

`CatchRecord.action?: string` を維持し、`actionLength?: 'short' | 'normal' | 'long'` を追加した。長さは秒数ではなく主観的な3段階。`src/db/database.ts` に選択候補・長さラベル・純粋な表示fallback・共通バリデータを置き、登録/編集とバックアップ復元で同じ値検証を使う。

アクションは単一select。全候補は以下の19件（未選択を含む）:

未選択、ただ巻き、ストップ＆ゴー、トゥイッチ、ジャーク、シェイク、シミーフォール、シミーアップ、リフト＆フォール、ステイ、マジックジャーク、デジ巻き、ボトムノック、ボトムバンプ、ボトムトレース、ドリフト、ダート、ボトムステイ、その他。

既存10種類を保持し、8種類を追加。ジャーク・シェイク・リフト＆フォールは重複させない。保存値にenum制限を追加せず、既存の未知の文字列はモーダルに一時候補として提示し、無変更編集で欠落・置換しない。既存の空文字列も無変更なら保持する。

| 操作 | actionLengthの扱い |
| --- | --- |
| 独立した新規キャッチ/バラシ | UI初期値normal（普通）。アクション未選択でも保存可。 |
| 旧記録の閲覧 | 未指定を表示上だけ普通とする。DBを書き換えない。 |
| 旧記録の編集開始 | refは未指定のまま、selectの表示だけ普通。 |
| 長さ以外の編集 | 未指定は欠落のまま、既存の明示値は保持。 |
| 長さを変更 | short/normal/longを保存。普通に戻した場合も明示normalとして保持。 |
| 前回と同じ | 従来どおり前回からアクション等をコピーして即保存。長さも明示値を継承し、前回が未指定なら新しいコピーも物理的に欠落を維持。 |
| コピー後の独立した次の入力 | 再びnormalから開始。コピーしたshort/longをフォーム初期値へ持ち越さない。 |
| 編集/新規入力のキャンセル | DB変更なし。 |

APIの旧呼出しも互換性を維持する。`registerCatch`へ長さを渡さなければ未指定のまま。`updateCatch`で省略すれば保存済み値または欠落を保持する。新規レコードのundefinedプロパティを保存せず、未指定と明示normalを区別する。全既存記録の一括補完は行わない。

結果区分、距離、速度、レンジ、魚種、タックル、場所の扱いは従来のまま。結果切替でアクション/長さをリセットしない。「前回と同じ」の魚種/タックル/今回の結果区分と現在エリアの既存ポリシーは変更していない。

## 互換性と非破壊性

非indexフィールドの追加であり、検索/クエリに新しいindexを使わない。DB v7の全version/stores宣言はmainと同一、migrationなし。バックアップ形式はv6を維持し、全16テーブルと新旧任意フィールドをそのまま往復する。旧v1〜v5も受入れ、長さがないデータを補完しない。不正なenum・型・nullは書込み前に拒否する。

登録/編集の検証は既存の単一トランザクション内で、所有ルアーの自動登録前に行う。失敗時は所有情報・釣果等を含めてrollbackする。バックアップ復元はファイル全体の検証が完了してから既存の保護付きtransactionに進む。未知のaction文字列は拒否・正規化しない。

Stage6の配布JSON・approvedレジストリ・公式バリデータ/apply、公式/user施設と名称snapshot、PWA実装とデプロイworkflowには差分なし。施設50/73と正式版1の履歴を保持し、既存釣行/日時、catch/lost、myLures、魚種、カタログ、タックルを自動変更しない。実機IndexedDBや本番バックアップは使用していない。

## iPhone実機受入れ（マージ/自動デプロイ後）

1. 既存PWAアイコン/サイトデータを残し、現在のバックアップを取得して記録と全マスターを確認。DB削除・本番復元試験は行わない。
2. ホームの明示更新操作後、新規キャッチで追加8種類が一度ずつ選べることと長さの初期値普通を確認。マジックジャーク/短いを保存し、編集で長いへ変更する。バラシと結果切替でも選択が残ることを確認する。
3. 旧記録を開き、未知のアクションと表示上の普通を確認。キャンセル、メモのみの編集でactionと長さの未指定が変わらないことを、バックアップJSONの対象レコードでも確認する。長さを明示変更すると値が保存されることを確認する。
4. 前回と同じで種類/明示長さがコピーされること、未指定の前回からは未指定が維持されること、独立した次の入力は普通から始まることを確認する。
5. イワセン9号池→ZERO号池で現在エリアを切り替えてキャッチ/バラシを保存し、前の名称snapshotが変わらないことを確認。マイルアー、各マスター、施設50/73の保持も確認する。
6. ソフトキーボード表示時のスクロール/保存/キャンセル到達、ライト/ダーク、編集中の更新延期を確認。圏外準備完了後に機内モード＋Wi-Fi OFFで完全終了→cold start→記録→完全終了/再起動し、保持とv6バックアップを確認する。

iPhone Safariの実キーボード/VisualViewportは未検証。390×500のChromium試験を実機合格とは扱わない。既存PWA利用者は明示更新までは旧UIを使う。JSの500 kB超サイズ助言はmainから継続しているが、build/SWは成功している。
