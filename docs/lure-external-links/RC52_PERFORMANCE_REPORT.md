# RC52-B PWA容量とオフライン設計

Windowsの隔離チェックアウトをNode 22.23.5と同じロックファイルでビルドした。比較元の532de49と起点eed3897はアプリ・ビルド設定が同一。比較先はf425308のアプリ・設定で、以降の変更は監査とテストと報告に限られる。バイト数は生成されたファイルを計測し、gzipはNodeの既定設定でファイル単位に圧縮した値。

| 指標 | 改善前 | 改善後 |
| --- | ---: | ---: |
| メインJavaScript | 2,067,539 B | 609,778 B |
| 最大JavaScriptチャンク | 2,067,539 B | 893,157 B |
| 最大チャンクのWorkbox上限までの余裕 | 29,613 B | 1,203,995 B |
| JavaScript合計 | 2,272,675 B | 2,273,129 B |
| JavaScript合計のgzip | 330,031 B | 328,119 B |
| dist全体 | 2,449,267 B | 2,450,267 B |
| dist全体のgzip | 437,774 B | 436,027 B |
| 事前キャッシュ対象の実ファイル合計 | 2,432,289 B | 2,433,134 B |
| マニフェストの項目／固有ファイル | 13／12 | 16／16 |

主JSに同梱していた外部参照・NOA定義、ルアーマスター、施設マスターを、Rolldownの静的チャンクに分けた。分離後は外部参照893,157 B、ルアーマスター535,732 B、施設マスター28,726 B。この分離で最大チャンクは56.8%縮小し、上限の57.4%が余裕になった。生成物の非圧縮総量は1,000 B増え、gzip総量は1,747 B減った。起動時間は計測範囲外。

すべての静的JSを既存のWorkbox globで事前キャッシュする。重複指定されていた pwa-client-check.js はglob側で1回収録し、importScriptsを継続。Workboxの2 MiB上限、スコープ、更新方式、ランタイムキャッシュ方針は維持した。事前キャッシュに外部URLは0件。

検証結果は [VALIDATION.md](VALIDATION.md) を参照。
