# RC52-C iPhone実機検証手順

ステータスは未実施。PlaywrightのモバイルChromium結果とは別に記録する。

## 準備

- iPhoneの機種、iOSのバージョン、Safariまたはホーム画面アプリ、テスト用URL、確認したコミットを記録する。
- Node 22で `bf1d812` とRC52-C候補を別々のチェックアウトに用意し、それぞれ `npm ci` と `npm run build` を実行する。既存の隔離HTTPSプレビューで、まず旧版の `dist/` を `/fishing-log/` に配信する。更新時に同じプレビューURLで候補版の `dist/` に切り替える。iPhoneが信頼する証明書を使い、`sw.js` と `index.html` を再検証できる配信設定にする。
- LAN内で検証する場合は、PCの旧版チェックアウトで `npm run preview -- --host 127.0.0.1 --port 4188 --strictPort` を起動する。iPhoneから到達できる検証用HTTPSリバースプロキシでパスを変えずにこのポートへ転送する。バックエンドへのHostは `127.0.0.1:4188` を使う。更新時は旧版のプレビューを止め、候補版から同じコマンドを実行する。iPhone側のHTTPS URLはそのまま使う。
- スキーム、ホスト、ポートの組み合わせが異なるプレビューには、本番のIndexedDBは共有されない。検証用の釣行、所有ルアー、撮影したダミー写真をプレビュー側で用意する。復元はこのプレビュー内、または別の隔離HTTPSオリジンで試す。本番のデータ削除、アプリのアンインストールは不要。
- Safariで開き、「共有」から「ホーム画面に追加」を選ぶ。「ウェブアプリとして開く」がある場合はオンにする。Safariとホーム画面アプリのどちらで実施したかをケースごとに残す。[Appleのホーム画面への追加手順](https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/27/ios/27)

## 実機の確認項目

| ケース | 操作と合格条件 |
| --- | --- |
| 初回起動 | オンラインでホーム画面アプリを起動して圏外利用の準備を完了する。表示された場合は「準備を完了して再読み込み」を押す。辞書で各メーカーの対象モデルと色を検索できる。 |
| 通常リンクと写真 | 辞書のNOA 1.8g「エルドラド」とNOA Jr. 0.9g「腹黒」で、ユーザー写真がなければ配色または汎用アイコンが表示され、各商品ページが開くことを確認する。共通色の「#1 ゴールド」に表裏のダミー写真を登録し、拡大・切替と別重量での共有を確認する。釣果登録でもユーザー写真が優先され、手動リンク設定が再起動後も保持されることを確認する。 |
| 圏外冷起動 | 機内モードを有効にし、Wi-Fiも設定でオフにする。ホーム画面アプリを終了して起動し直す。辞書、所有ルアー、端末写真と配色を確認し、釣果を保存する。もう一度終了して開き、保存した釣果を確認する。 |
| 更新保留と適用 | 旧版で釣果編集を開き、検証URLを候補版に切り替える。接続を戻し、更新表示後も入力中の画面が自動で閉じないことを確認する。編集内容を保存し、ホームで「更新して再読み込み」を選ぶ。更新後、釣行、釣果、所有、端末写真、手動リンクが保持され、圏外冷起動もできることを確認する。 |
| バックアップ復元 | 検証データの通常JSONと写真バックアップをそれぞれ「ファイル」へ保存する。隔離した検証データに復元し、釣行・釣果の関連、所有、写真の表示と手動リンクを確認する。 |

検証記録には各ケースの成功・失敗・未実施、期待と異なる操作、再現率を記入する。添付には検証用データだけを使う。
