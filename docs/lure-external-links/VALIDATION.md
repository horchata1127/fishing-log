# RC47-A 検証記録

Windowsの隔離テストDBとPlaywright専用ブラウザープロファイルを使用した。非NOAの画像応答は合成データ。既存NOAの実出典画像は、11月23日のデコード証跡と現行ポリシーで照合した。

| 実行 | 結果 |
| --- | --- |
| `npm.cmd test` | 726件中721成功、5スキップ、失敗0 |
| `npm.cmd run build` | 成功。既存のチャンク容量警告あり |
| `npm.cmd run test:e2e:typecheck` | 成功 |
| `npm.cmd run test:e2e` | 全体実行は232件中230成功、2失敗。失敗した対象は再実行で成功 |
| `npm.cmd run test:offline` | 70件すべて成功。最終ビルドでNOAのPC・モバイル2件も再実行して成功 |
| 非NOAの合成参照の再実行 | PC・モバイルChromiumとも成功、計2件 |
| `git diff --check` | 成功 |

単体テストの初回は、既存テストが要求するGit管理外の公開カタログのテスト用ファイルが見つからず1件失敗した。ローカルに保存済みの同ファイルを一時配置して全件を再実行し、終了後に作業用コピーを削除した。スキップ5件は別の任意バックアップを必要とする既存テスト。今回指定の原本を使うテストは実行され、写真登録の前後で全既存行・ID・値が一致し、原本SHA256が変わらないことを確認した。

合成参照では、辞書・所有ルアー選択・カタログ選択、画像拡大、SVG切り替え、404・アクセス拒否・不正画像での代替表示、商品リンクの維持、圏外で外部画像要求が出ないこと、通信復帰、釣果下書きとDBの維持を確認した。成功画像のブラウザー内再利用で初回テストが失敗したため、失敗種別ごとに合成URLを分け、各ケースで実際に画像要求が発生するようテストを修正した。

全体の画面テストで失敗した既存RC27のエリア選択は、テスト中に選択肢が表示されなくなった。同じアプリ実装・テストで単独再実行し、成功した。

通常バックアップ・写真バックアップの形式、DBスキーマ、マスター適用処理に差分なし。既存NOAの共有色ID・ユーザー設定・配色の回帰は既存テストを使った。実機iPhone Safariと、ユーザー端末にだけ保存されている写真そのものは未検証。

棚卸しの再実行は、ルートから `node scripts/audit-lure-external-links.mjs "<通常バックアップのパス>"`。原本の前後SHA256を比較し、対象4テーブルの件数が明細と一致することを確認する。
