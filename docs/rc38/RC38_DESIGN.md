# RC38 設計

2026-11-04。RC37はPR #37でmainへマージ済み。開始時main / origin/mainは `23e0774`、fetch後の差分なし。ここから `feature/rc38-moca-dr-f-rattle` を作成した。

## カタログと照合

既存ID128 `MOCA DR Rattle 2HOOK` はF/SS不明のまま保存する。うぐいすもち・さくらもち・寿の3色、所有、関連釣果、代表配色も変更しない。重量だけでF/SSを判定しない。

RC38は `MOCA DR-F Rattle 2HOOK`（30mm / 2.1g / F / ラトル）と `MOCA DR-SS Rattle 2HOOK`（30mm / 2.4g / SS / ラトル）を別モデルにする。通常DR-Fとも別キー。型式不明名を別名には登録しない。

RC37の阻止規則は履歴再現用に残し、確認済み2商品のRC38パックだけに `preserveAmbiguousModel` を指定する。この指定は型式不明モデルの存在による追加阻止だけを解除する。名称照合、親メーカー・シリーズ、重量・全長の検証、重複モデル保留、モデル内カラー照合、コード・限定区分・JAN競合の保護は継続する。

RC37パックは変更せず累積マニフェストで明示的にRC38を合成する。RC37の14色の根拠とRC38の26色の根拠を `sources` に保持する。過去の取り込み履歴は変更しない。版は `RC38-moca-rattle-2026-11-04`、matchingVersion=3。旧版の監査は `buildManifest(false)` で再現できる。

DR-FはRC37の7色と城峰16色の重複4色を統合して19色。DR-SSは7色。新規variantの `catalogEvidence` はRC38、販売店確認、確認日、色ごとの販売店URL、確認できたJANを保存する。メーカー公式確認・写真配色は推測しない。店舗の商品説明・画像は同梱しない。

## 適用とデータ保護

既存の「ルアーマスター管理 → 最新版との差分を確認 → バックアップ保存 → 確認して更新」を使用する。起動時追加なし。DBスキーマとバックアップ形式の変更なし。追加処理は既存のDexieトランザクションを使用し、途中失敗時は全カタログ追加をロールバック、失敗履歴だけを記録する。

既存行の更新・削除・名称変更・統合なし。RC38による自動所有追加・釣果変更・MVP変更・配色生成なし。再適用ではモデル・カラー・所有追加0件。

## 所有と釣果編集

通常マイルアー画面でRODIO CRAFT → MOCA → DR-Fラトル → さちおの茶を選択して登録する。登録時に同じvariantの有効な実所有があれば再利用する。未確認・仮個体は実所有として再利用しない。実物を複数持つ従来用途は「同じカラーの別個体として追加する」で明示指定できる。既存の複数個体は削除・統合しない。

釣果は本人確認後に通常の編集画面から変更する。個別ID・差分・手順は [監査](RC38_CATALOG_AUDIT.md) を参照。確認付き一括修正は今回追加しない。MVPは釣果編集後のサマリーから再指定でき、PNGは保存済みの名称・カラーを反映する。

## 検証方針

RC37の旧保留を再現し、RC38では2モデル26色を別途追加することを確認する。実バックアップはfake-indexeddbへ復元して全テーブルの既存行を比較する。合成データで気象、メモ、MVP、配色、旧バックアップ互換、失敗ロールバックを確認する。E2E・圏外試験は隔離originと合成データを使用する。実iPhone Safari/PWAは別途確認が必要。
