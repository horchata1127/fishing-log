# Fishing Log RC21 仕様書 — 保留282色のモデル解放

作成日: 2026-10-12
前提: RC20 PR #15 が main にマージ済み。端末バックアップの実測は 1888 → 1936 カラー（48件増）、既存全レコード不変。

## 目的と範囲

RC20で「hold_missing_model」として保留された **ベルベットアーツ11モデル・213色、ロブルアー7モデル・69色、計18モデル・282色** の公式確認済みデータを、モデル登録を経て追加できるようにする。

**非対象:** 現時点で色名が確認できない色、VAパペットサーフェスの未確認色、1089工房の追加未調査モデル・試作品、バラシ記録。保留メモ項目まで色として扱わない。

## 実装要件

1. **既存メーカーIDを再利用**（ベルベットアーツ 62、ロブルアー 71。端末照合が必要）。シリーズ名・モデル名・重量・所属の一致を先に検査する。重複・曖昧一致がある場合は書き込まず保留に戻す。
2. RC20公式カラー原本 `docs/rc20/RC20_OFFICIAL_CATALOG.json` の18対象からモデルおよびカラーを作成する。`allowNewModel` を単純に全件 `true` に書き換えるだけにせず、**明示的なモデル許可リスト**と商品検証済みフラグを実装する。
3. 未登録シリーズ・モデルは必要な分だけ追加する。既存モデルがあればIDを維持し、そのモデルの不足カラーのみ登録する。カラーは**モデル別**のデータとして保存し、別重量モデルに横流ししない。
4. 追加予定の事前確認で、追加予定シリーズ・モデル・色数と既存ID、保留理由、公式出典を表示・CSV保存できるようにする。**追加ボタンで初めてDB更新**。
5. 一つのDexie `rw` トランザクション内で再照合して適用。途中失敗は全ロールバック。二度目の適用で追加0。DB v7維持を原則とする。
6. `trips`, `catches`, `myLures`, `fishSpecies` および既存マスターのレコードは書き換え・削除しない。特に巾着田 tripId 10 / catchId 11–14、HUNT GRANDE T-15/T-18 のカラーと所有参照を維持。
7. 公式色がカタログに増えても所有ルアーは自動的に増やさない。RC20の48追加色も重複させない。
8. RC21適用前にiPhoneからバックアップを書き出し、適用後にもバックアップ比較。Safari PWA・オフライン・再起動テスト。

## 想定受入結果（現状バックアップからの純粋追加の場合）

- ルアーカラー: **1,936 → 2,218** （+282、ほかに変更がない場合）
- シリーズ: **135 → 最大143** （対象シリーズ8種。すでに存在すれば追加件数は少ない）
- モデル: **305 → 最大323** （対象18種。すでに存在すれば追加件数は少ない）
- メーカー: 80 → 80
- 釣行: 5 → 5、釣果: 7 → 7、マイルアー: 4 → 4
- 既存レコードID・内容変更/削除: **0**
- 事前照合では追加予定282色、反映後再照合では追加予定0色（実機の他の変更がない場合）。別の確認待ち項目は残る。

## 開発指示（Codexへ）

- `main` を更新し、新規ブランチ `feature/rc21-unlock-held-models` を作成。ただし既に適切なRC21ブランチが存在すれば再利用。
- RC20の既存パック、パーサ、検証処理と `docs/rc20/RC20_CATALOG_DIFF.csv` を活用。適用予定の再集計は各種 `hold_*` 行の単純総数ではなく、公式原本のモデル別 `colors` 配列から計算すること。
- ビルド、単体、E2E、オフライン、並行反映、失敗ロールバック、iPhone既存データ保全のテストを追加。未追跡の手元資料は変更しない。
- `docs/rc21/RC21_IMPLEMENTATION.md`, `RC21_VALIDATION.md`, `RC21_PR_DRAFT.md` を作り、コミット・push前に作業内容を報告。
- 勝手に本番データへ更新をかけたり、mainにマージしたりしない。

## 補足

「全保留をゼロ」にする仕様ではない。今回対象は**名前・出典がRC20公式原本にある282色**。確認不足のその他保留は公式確認ができるまで残す。
