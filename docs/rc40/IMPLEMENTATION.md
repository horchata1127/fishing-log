# RC40: 釣果登録時のカラーチェンジ

実装日: 2026-11-15

## 調査・影響範囲

- `CatchModal.vue` が新規登録・編集を兼ねる。「前回と同じ」は `registerSameAsPrevious` により即保存するため、その処理を変更しない。
- カラーの内部IDは `lureVariants.id`、モデルとの関連は `lureVariants.modelId`。釣果は `lureVariantId` と任意の所有個体ID `lureId` を保存する。独立した釣果のモデルID項目は追加しない。
- `loadLureChoices` がIndexedDBからモデル・カラー・実所有・配色情報を取得済み。ここに任意の釣行IDを渡し、同じ読み取りトランザクション内で直前のモデルを解決する。
- 変更範囲は上記取得処理、`App.vue` の受け渡し、新規登録モーダル、テスト、RC40文書。DB、既存履歴、マスター、所有管理、バックアップ形式を変更しない。

## 動作

1. 新規登録フォームを開く際、現在の釣行の `caughtAt` が最新の記録を対象にする。同時刻は既存の前回再利用と同じ並び順を使う。
2. `lureVariantId`、または所有個体の `variantId` からモデルIDを解決する。カラー名が未設定でも参照があれば利用できる。所有個体が非アクティブでもモデルの特定は可能。
3. 「前回と同じ」と同階層にパレットアイコン付きボタンを配置。通常は横並び、狭い幅では折り返す。前回なし・モデル不明では無効化し、名前による推測や古い記録への遡及を行わない。編集画面には追加しない。
4. 既存のモーダル／ボトムシートのスタイルで対象モデルIDのカラーだけを表示。実所有を優先し、未所有も選択可能。名前検索と50件ずつの追加表示に対応する。配色は `VisualColorPreview` を再利用する。
5. カラーを選ぶと、既存のルアー選択処理でモデル名・カラー名・参照ID・配色を反映する。旧カラーの配色を残さない。他の入力値は変更しない。
6. 保存には既存の `linked` 選択と `registerCatch` を利用する。選択時には書き込まず、「保存する」で確定する。所有カラー・未所有カラーとも、所有個体の追加・変更は行わない。保存済みの `lureVariantId` から正しいモデルを参照できる。
7. 閉じる／キャンセル／背景タップ／Escapeでは値を変更しない。空一覧・検索結果なしを区別して案内し、通常のルアー選択へ戻れる。

## 実カタログの例

同梱マスターを既存の更新UIで適用したテストDBで、`MOCA DR-F 2HOOK` の「ミルクココア」と「さちおの茶」が存在することを確認。前者で釣果を保存した後、カラーチェンジで後者を選び、対象モデルに属する正しいカラーIDで保存できた。

ラトル版・DR-SS・同名の別モデルはモデルIDで区別する。ユーザーの実釣行バックアップは変更していない。

検証結果と制限は [VALIDATION.md](VALIDATION.md) を参照。
