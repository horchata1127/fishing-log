# RC27 既存釣行の施設紐付け

## 基点・照合

PR #26のGitHub上のマージを確認し、最新main `c132705f8e717df8c93f1964e3c75c2e1aaa46cf`から`feature/rc27-trip-facility-link`を作成。

既存の保存先はFishingTripの`facilityId`・`fishingAreaName`・`currentZoneId`。釣果側は独立した`facilityId`・`zoneId`・`locationSnapshot`を持つ。釣果の施設参照が親釣行の現在の施設と異なっていても、保存元の施設・エリア同士の参照は維持できる。

添付指示書の日本イワナセンター9エリアについて、正式JSONとID・名称を機械照合して一致を確認した。掲載順は指示書の表と異なり、正式sortOrderはZERO号池第2→ZERO号池第1→1号池…→9号池。承認済み50施設・73エリアと順序は変更しない。

## 施設選択・保存

釣行詳細に現在の施設名・IDと「施設を設定・変更」を追加。終了済み釣行でも利用できる。

1. ボタンで中央・縦スクロール可能な編集モーダルを開く。
2. 配布中の正式施設を名前で検索し、選択する。既存IDは初期値として表示するが、保存前に影響を確認する。正式候補外の既存IDは保持表示のみ。
3. 施設IDなしで名称が一致する場合は候補を案内するだけで、自動選択・保存しない。未登録の自由入力名称もキャンセルすればそのまま保持する。
4. 選択時に変更後の名前・ID、旧施設／所属未確認のエリアが残る記録数（釣果／バラシ別）と詳細を表示する。
5. 不整合な旧エリアまたは現在エリアの解除がある場合は、確認チェックを付けるまで保存できない。
6. 保存ボタンでのみ確定する。釣行IDと日時等は維持し、正式名称に合わせる。ページ全体をリロードせず詳細・ホーム一覧・エリア候補を更新する。

施設マスターへの新規登録、自由入力名からの自動紐付け、起動・表示・復元時の補完は追加しない。釣行ID 12や特定施設への特別分岐はない。

## 整合性と履歴保護

`tripFacilityLink.ts`は、選択施設が配布中の正式施設か検証する。プレビューは読み取り専用。保存トランザクションで釣行・釣果・対象施設・エリア定義を再確認し、プレビュー後に変更されていれば再確認を求めて拒否する。

保存時に書くテーブルはtripsのみ。変更項目は施設IDと施設名、および必要な場合のcurrentZoneId解除のみ。

- 釣果・バラシの施設ID、エリアID、名称snapshot、メモ、時刻等を変更しない。放流・ペレット・気象・地点・出典・ライセンス情報も変更しない。
- 釣行の現在エリアが新施設に属さない場合は、IDを表示したうえで明示確認を受けて未設定にする。黙って削除せず、釣果に保存された旧エリアは解除しない。
- 施設変更後の釣果編集では、旧エリアIDを保持表示し「旧施設のエリア」と案内する。新施設の候補を手動選択して保存した場合だけ、RC26の既存保存処理でその釣果を再設定する。
- タイムラインでは現在の正式エリア所属を読み取り、旧施設・所属未確認のエリアを専用のフィルタキーと表示名で分離する。同名や不正な同じzoneIdがあっても新施設のグループに混ぜない。マーカー詳細・履歴にも案内を表示する。
- 施設変更時はエリアフィルタを全体へ戻す。エリア編集等で現在の選択肢が消えた場合も全体へ戻す。総釣果・平均ペース・気温・イベントは維持する。
- 保存済み手動地点と気象は前の取得地点のまま保持する。施設が異なる場合は注意を表示し、再取得前に地点の確認を案内する。地点再利用候補だけは新しい施設IDで読み直し、自動通信・自動適用しない。

メモの「9号池」「ゼロ号池」からIDを割り当てない。ZERO第1／第2も推測しない。エラー時は保存トランザクションをロールバックし、モーダル入力と既存データを保持する。

## iPhone Safari／PWA確認手順

実機の本番IndexedDBや本番バックアップを検証に使わず、検証用origin・合成記録を使用する。

1. 施設IDなし・名称だけの釣行を開き、施設編集モーダルで検索する。名前が一致しても未選択であることを確認する。
2. 正式施設を選択してキャンセルし、元の値を保持することを確認。再度選んで保存し、名称とID・釣果7匹・平均0.75匹/時を確認する。
3. 釣果編集で9エリアが表示されることを確認し、1件だけ手動設定する。メモが残り、エリアフィルタ・棒グラフ・表示中件数が更新されることを確認。
4. 別施設に変更し、影響件数・旧エリアID・現在エリアの扱いを確認してから保存する。旧エリアは残り、新施設のエリアと区別されることを確認する。
5. 画面幅をはみ出さず、縦スクロールで保存・キャンセルに届くことを確認。検索・選択・確認チェックは44px以上の操作方式を使用する。
6. PWAの圏外準備完了後、機内モードで完全終了・再起動し、施設設定・エリア編集を行う。再起動後も保持し、検証用v7バックアップの往復で全19テーブルを確認する。

## 残存事項

- 実機Safari／ホーム画面PWAは未確認。自動試験はiPhoneサイズのChromium。
- 旧施設の釣果は自動で新施設へ移さない。必要な各記録はユーザーがRC26の編集で再設定する。
- 元から参照先が壊れている記録を自動修復しない。そうしたバックアップは従来の検証で復元を拒否される場合がある。正常な旧施設・エリア参照を保持した施設変更はv7往復を確認済み。
- 保存中・影響読込中はモーダル操作を制限する。別画面での変更は再プレビューが必要。
- 既存の500kB超bundle警告は継続。

DB v8・19テーブル／気象ありバックアップv7、旧v1〜v6入力、正式施設50件・73エリア、PWA更新方式・workflow・依存関係は変更しない。Draft PRで終了し、マージ・自動マージ・main直接push・デプロイを行わない。
