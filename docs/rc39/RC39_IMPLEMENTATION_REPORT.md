# RC39 釣果タイムライン画像エクスポート 実装報告

2026-11-04。釣行サマリーとは独立した、釣れたタイミングと環境の流れを振り返るPNG出力を追加した。

## 出力仕様と使い方

釣行詳細の「統合タイムライン → タイムライン画像を保存・共有」を開く。必要な項目を選び、「タイムライン画像プレビューを作成」後に「タイムライン画像を保存」または「タイムライン画像を共有」を押す。既存サマリーは別の出力欄のまま保持し、保存ボタンを「サマリー画像を保存」と明示した。

出力は **横1080px、縦1600px以上の可変高さPNG**。日付、釣り場名、JST表示範囲、エリア条件、6種類の凡例、気温線、釣果・バラシ・放流・ペレット・気象／環境マーカー、補足注記、気象データ出典、フッターを含む。イベントの日時・内容、時刻不明・範囲外の記録も画像の下部に残す。

6種類の表示ON/OFFに対応。初期状態は全種類ONで、任意のメモ抜粋はOFF。メモは最大400 Unicode文字＋省略記号、イベント説明は全文。現在のエリア絞り込みを反映し、画面のズームや横スクロール位置には依存しない。画像側の表示切替は画面側の気象表示切替と独立する。

既存タイムラインと同じデータモデル・表示範囲決定・欠損処理・マーカー衝突配置を使う。タイムライン専用のHTML/SVGを描画するため、画面のスクリーンショット保存ではない。時刻はJST、概算は「約」と破線で区別し、気温を釣果時刻の実測値として表示しない。

プレビュー生成後は同一Fileを保存・共有し、保存時に再描画しない。設定や記録の変更時には古い画像を無効化する。ファイル名は `fishing-log-YYYY-MM-DD-timeline.png`。対応環境ではWeb Share APIでファイル共有し、非対応時はPNGを保存する。共有キャンセル時に保存は開始しない。iPhone向けにプレビュー画像の長押し保存も案内する。

## 検証結果

最終結果: **単体660/660成功（skipなし）、画面E2E 28/28成功、オフライン6/6成功**。アプリ型チェックを含むビルド、E2E型チェック、`git diff --check` も成功した。

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:e2e:typecheck
npx.cmd playwright test tests/e2e/rc39-timeline-image.spec.ts tests/e2e/trip-timeline.spec.ts tests/e2e/rc35-weather-notes.spec.ts tests/e2e/rc36-summary-export.spec.ts tests/e2e/rc37-moca.spec.ts tests/e2e/rc38-moca.spec.ts

git diff --check
```

- 時刻範囲・凡例・注記・全マーカー・気温欠損を単体と画面の両方で確認した。PNGのグラフ領域のピクセルでも気温線・キャッチ・バラシの描画を検証した。
- プレビューと保存PNGのSHA-256が一致し、共有へ渡すFileのSHA-256も同じことを確認した。
- 長い日本語・4日間・同時刻の多数マーカーでも、全レコード・説明・フッターが画像内に収まることを座標とPNG寸法で確認した。
- 項目やエリアを変えるとプレビューと保存状態を無効化する。気温なしでも生成できる。PNG生成失敗後の再試行、共有キャンセル、共有非対応時の保存を検証した。
- 既存のタイムライン、RC35気象・メモCRUD、RC36サマリー／MVP／PNG、RC37/38マスター更新と復元・所有登録の回帰テストが成功した。
- PWA準備完了後にオンラインのブラウザを閉じ、圏外の永続ブラウザで再起動してから初めてPNGを生成した。レンダラーのチャンクも圏外で利用できることを確認した。

画面試験はdesktop/mobile Chromium。初回検証で見つかった重複テキスト参照を避けるため、出力UIを開くまで画像用DOMを作らない方式に修正した。最終の全28件では既存テストも成功している。

## データ保護・提供バックアップ

画像用コードにDB書込み・DB読込み・気象API取得を追加していない。画面から渡された保存済みの値だけを参照し、データモデル、SVG用データ、既存レコードを変更しない。DBスキーマ・バックアップ形式の変更もない。

E2Eではプレビュー生成・保存・共有・失敗再試行・フィルター変更の前後で全テーブルを比較し、値が変わらないことを確認した。オフラインでも全表を比較し、再読込み後も同じことを確認した。ブラウザ試験は合成データと専用originだけを使い、稼働端末DBや実Chromeプロフィールにはアクセスしていない。

提供された `docs/rc39/RC38_fishing-log-backup-2026-11-04.json` は読み取り専用で確認した。内部形式はv9。釣行ID15（2026-11-03 多摩湖駅前フィッシングエリア）は06:53〜13:36 JST、11キャッチ・6バラシ、保存済み気象24時間分、イベント0件。既存モデルから気温線1区間・全17マーカーを画像用データに投影でき、入力は変更していない。原本に放流・ペレット・観測イベントを追加していない。元指示書・原本バックアップ・無関係な未追跡資料はコミット対象外。

## 実機確認結果と既知の制約

**iPhone Safari実機・iPhoneホーム画面PWA実機での保存、共有、長押し、圏外生成は未実施。** Chromiumのモバイル条件とPWA試験は実機Safariの代用ではない。

実機で確認する項目: PWA更新・圏外準備、プレビュー生成、写真／ファイルへの保存、長押し保存、共有シートへの画像受渡しとキャンセル、通常・密集PNGの日本語と最下部、圏外での再起動後の初回生成。実機での共有先への投稿は本実装の試験には含めていない。

高さ12000px超、横方向のはみ出しは切り落とさずエラーにする。対象やエリアを絞って再試行できる。上限内でも端末のキャンバス・メモリ制限で失敗し得るため、全iPhone機種で生成できるとは保証しない。ページ分割は行わない。長期間の横軸は同じ幅へ圧縮されるが、マーカーは衝突段へ展開して保持する。プレビューは表示用に縮小されるため、文字を詳しく読むときは保存画像を拡大できる。

通常グラフのタップ詳細・時間別釣果棒グラフ・取得地点詳細・RC36サマリー表はこの画像へ混在させない。イベント内容は下部の説明欄で確認できる。外部フォント・画像の読込みは不要。既存の大容量JSチャンクに関するビルド警告は残る。
