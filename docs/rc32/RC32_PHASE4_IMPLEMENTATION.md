## 実装機能と使い方

ホームの「ビジュアルカラー辞書」を開き、「推定配色を一括取り込み（管理）」を展開する。

1. 「推定件数を確認」で端末に実在するカタログを読み取り、追加・保持・保護・保留・推定不可の件数を表示する。
2. 必要なら先頭30件の配色例・根拠・確信度目安を確認する。この段階ではDBに書き込まない。
3. 「確認した推定配色を取り込む」を押すと、新規の推定配色だけを追加する。
4. 辞書の色検索で候補を探し、釣果入力へ再利用する。
5. 推定が違う場合や確認できた場合は「代表配色を編集」から調整・保存する。保存後は手動編集・確認済みとして保護される。

この管理操作は、通常の釣果登録から開く辞書や、仮カラー紐付け中の辞書には表示しない。起動時・復元時の自動取り込みはない。

既存配色は推定済みのものも含めて保持する。今回は既存推定の更新を行わない追加専用方式とした。結果は「名称推定・未確認」と「手動編集・確認済み」を区別し、未推定・未登録も表示する。アイコンには共通SVGを使用する。

## 名称推定器

`src/utils/autoColorInference.ts` の純粋関数 `inferColorName()` に再実行可能なルールを定義した。推定器バージョンは `rc32-name-v1`。

- NFKC、英大小文字、ひらがな・カタカナ、半角カナ、英語CamelCase、空白・ハイフン差を正規化。
- 長い名称を先に処理し、ダークブルー等をブルーとして重ねて解釈しない。
- 和名・英名・同義語から48色・12属性の固定IDへ変換。
- 赤金・黒金等の複合色、クロまんじゅう・ワカサギ・ペレット等の明示した慣用名に対応。
- 確認できた色は最大3色。4色以上や競合する模様は自動確定しない。
- 部位を推測せず、共通配色として保存。写真や仕様にない背・側・腹を作らない。
- 模様・特殊属性は名称に明示された語だけを設定する。金色だけでメタリック属性を追加しない。
- 未知の固有名詞、製品コードだけの名称は未推定。`赤城`の一文字を赤と解釈したり、`Blueberry`をBlueとして扱ったりしない。
- 色が分からず属性だけ明示されている場合は、その属性だけを保存する。白等の代替色を捏造しない。

保存時はorigin=name、userEdited=false、confirmed=false。evidenceには入力名称、推定器版、適用ルールと一致語、確信度目安、存在する場合は元カタログの出典URLを残す。追加したevidenceフィールドは任意であり、旧v8データを補完しない。

### 確信度の意味

| 目安 | 意味 | 対象数 |
|---|---|---:|
| 0.85 | 明示的な語が解釈でき、未解釈部分がない | 310 |

## 安全な差分取り込み

`planAutoColors()` は、カタログ配列と既存プロフィールを読み取って計画を作成する。端末向け `previewAutoColors()` と開発用監査で同じコードを使う。

| 区分 | 動作 |
|---|---|
| 新規追加 | 推定でき、IDと自然キーが一意で、既存配色がない |
| 既存保持 | 既存の未確認推定配色がある。更新しない |
| 保護 | 既存がユーザー編集済み、確認済み、またはユーザーorigin |
| 保留 | 親参照不正、自然キー／ID重複、複数候補、既存IDとキーの不一致、参照解除済み等 |
| 推定不可 | 既存配色がなく、名称からも推定できない |

プレビューの比較トークンには推定器版、カタログ4テーブルと既存プロフィール全体を含める。適用時にトランザクション内で再計画し、カタログまたは配色が変わっていたら一切追加せず再確認を求める。

保存層へ追加専用の `addInferredVisualProfiles()` を追加した。配色状態・根拠・公式IDと自然キーの参照を検証し、既存プロフィールへの更新は行わずbulkAddする。一意索引による衝突や途中の失敗では、取り込み全体をロールバックする。検証・保存は単一トランザクションで、カタログ・myLures・釣果・イベント等には書き込まない。

### 英語の名称をコードと誤認しない修正

監査で、既存のコード抽出が `All Brown` の `All` や `Ghost Food` の `Ghost` をコードと扱う問題を確認した。今後の自然キー生成では、証跡に明示されたコード、または先頭の数字を含むコード形式だけを採用する。英語の一般語は名称として扱う。

既存プロフィールの自然キーは移行・書換えしない。過去に一般語をコードとして保存したプロフィールと新しい自然キーが一致しない場合は保留し、自動統合しない。明示証跡のアルファベットだけの正規カラーコードは引き続き使用できる。

## 精度の限界・残課題

- 名称とルールの一致を検証したもので、1,410件の実物塗装・写真に対する正解率は未計測。
- 推定できた名称でも、未解釈の修飾語やメーカー独自の意味が残るものがある。仮配色・未確認として扱う。
- 属性のみ243件は色の逆引きで発見できる色を増やさない。既知の属性だけを残すための推定である。
- 写真抽出・画像対応表の検証は今後の作業。今回の実装にネットワーク取得や大量スクレイピングは含めない。
- 自然キー競合22件と未推定1,473件は自動で解消しない。元マスターの整理や明示的な手動確認が必要。
- 既存推定を新しい推定器版で一括置換する処理は未実装。今回の再実行は保持・追加専用。
- iPhone Safari実機の性能・表示は未検証。モバイル検証はChromiumのiPhone画面・タッチ条件。
- 新ビルドの公開・配布は行っていない。
