# RC41 実装

## 利用方法

「現在のエリア」直下の「釣り座・エリアマップ」セクションに、地図／位置マーカーのアイコンと補足を付けた2つの独立ボタンを縦に配置する。44px以上のタップ領域、ボタン間の余白、キーボード用フォーカス表示を確保する。

メインメニューまたは釣行画面の「エリアマップ管理」で施設を選び、「＋エリアを追加」からマップを作成する。メインメニューでは釣行未開始でも利用でき、既存の施設マスターを名前で検索・選択できる。選択中の施設名は一覧・編集中の両方に表示する。登録済みエリアを選ぶか、既存のユーザーエリア登録を使って新しいエリアを作る。マップ名は変更可能な表示タイトルであり、公式エリアの名称を変更しない。

両方の導線は同じ `AreaMapManager` を使用し、保存後に閉じると元のメインメニュー／釣行画面へ戻る。保存したマップは次回以降の釣行とも共有する。施設切替時には古い一覧を消し、最新の読み込み結果だけを表示して別施設のマップが混ざることを防ぐ。検索中でも選択済み施設は維持する。ホームで管理モーダルを開いている間はPWA更新を保留し、編集中データの再読み込みによる破棄を防ぐ。

マップ未登録の釣り座イベント画面では「エリアマップを作成」から同じ管理画面を開ける。イベント画面をアンマウントせず、その上に管理モーダルを表示するため、入力済みの日時・メモ等を保持する。管理画面を閉じると候補を再取得し、マップ選択欄にフォーカスを戻す。UI導線改善ではDB・バックアップ・マップ保存・イベント保存処理を変更していない。

ポンド8種・河川5種のテンプレート、90度回転、左右反転、縦横比の調整を用意。詳細な形状編集では制御点をドラッグできる。水域は閉じた多角形として扱い、円・楕円・蛇行等は細分化した輪郭で表す。制御点の範囲、最小辺長、面積、自己交差を検証する。

「インレット追加」「アウトレット追加」で岸をタップすると特徴物を追加する。複数配置、ドラッグ、名称・メモ、削除に対応。近接した特徴物は一覧から選択すると手前に表示され、選んだものを移動できる。追加・削除・形状調整は「元に戻す」で取り消せる。テンプレート自体を変更する場合は、特徴物の配置を解除する確認を表示する。

「釣り座を記録」でマップを選び、水際を1回タップして位置を指定し保存する。マーカーのドラッグ、ズーム中の調整、2本指でのズームと移動、背景ドラッグ、ズーム・移動ボタンに対応。方向は任意で8方向または1度刻みの調整を使用する。方向0度はマップの右、90度は下であり、GPS方位ではない。

釣り座はイベント一覧と統合タイムラインに表示され、詳細から保存時のマップを確認できる。既存の日時・メモ編集・削除を利用できる。同じ釣行の直前の釣り座を初期表示し、別マップを選ぶと座標・方向を解除する。参照先がなくなっても保存時スナップショットを表示する。

## 永続化と整合性

- DB v10→v11。新設は `areaMaps` の1テーブルのみ（主キーid、索引facilityId・zoneId）。旧22テーブルのレコード・キー・索引への移行書込みはない。
- マップは施設・エリアIDに関連付け、釣行を削除しても残る。新規エリアは `addUserZone` により既存の `zones` に登録する。マップとエリアの追加は1トランザクションで実行し、失敗時には両方を取り消す。同名エリアを自動統合しない。
- 特徴物はマップに埋め込み、辺番号と0〜1の比率で岸に固定する。頂点の順序を維持するため、通常の形状編集・回転・反転・比率変更後も同じ辺に追従する。
- 釣り座イベントは `type: position` と `fishingPosition` を追加。正規化座標、岸の参照、任意角度、マップ全体のスナップショットを保存する。釣果の構造は変更しない。
- マップの編集はrevisionを増加。過去イベントは自身の版を保持する。過去の版で釣り座・方向を編集する場合もその形状を使う。新規イベントには現在の保存済みマップを要求し、競合時は再選択を案内する。
- マップ削除は確認付き論理削除。過去イベント・エリア自体は削除せず、通常の候補だけから除外する。マップとイベントの編集には既存値との比較による競合検出を行う。
- 検証は既存方針に合わせDBの型・検証関数に集約。画面、イベント保存、バックアップで同じ検証を使う。

## バックアップ

RC41のマップまたは釣り座イベントが存在するとv12を出力し、`areaMaps`・特徴物・保存時形状・座標・方向を含める。それらがなければ従来の形式選択を維持する。復元履歴の形式検証もv12に対応した。

v12のマップは復元時に置換し、ID重複、形状・座標不正、施設・エリア参照不正、同IDの異所属衝突を検証する。全処理は既存の復元トランザクション内で行う。再取り込みでマップ・イベントを重複追加しない。復元監査履歴は従来仕様どおり追加する。

旧形式を復元した場合は、釣行に依存しない現在のマップを保持する。施設・エリアは既存の統合処理によって保持される。釣行・イベントは従来どおり復元内容で置換され、旧釣行IDへ位置を誤接続しない。
