# RC41 設計

## 調査結果と開始地点

RC40のmainマージ（451a629）を確認し、`feature/rc41-area-map-fishing-position`を作成。既存の未追跡バックアップは作業対象外。

- Vue 3 / TypeScript / Dexie。DB v10、バックアップはデータに応じv2〜11。PWAはローカル資産を事前キャッシュする。
- 施設 `facilities` とエリア `zones` は文字列ID。公式データは適用メタデータと一致する必要があり、ユーザー追加は既存の `addUserZone` を利用する。名前でエリアを自動統合しない。
- `tripEvents` は釣行ID、発生日時、種別、エリア、メモを保持。`TripEventEditor` / `saveTripEvent` が日時検証・楽観的競合検出・編集・削除を担当する。
- RC35は観測イベント、RC36はレポート、RC37/38はモカマスター、RC39はタイムライン画像、RC40は釣果カラー選択。釣果・ルアー・所有レコードは今回変更しない。

## 保存・互換性

DB v11で `areaMaps` のみ追加。既存テーブルの書換え・補完はなし。マップは施設IDと既存エリアIDに関連付け、釣行から独立して再利用する。マップ名は編集可能な表示タイトルであり、公式エリア名称を上書きしない。未登録エリアは既存のユーザーエリアとして追加する。

マップ内に輪郭と特徴物を一緒に保存し、特徴物だけが孤立する状態を避ける。各輪郭頂点の順序を維持し、特徴物は辺番号＋辺上の比率で固定する。回転・反転・縦横比・頂点移動後も同じ辺上に維持する。河川も両岸と上下流端を閉じた水域として表現する。曲線形状は十分な数の頂点で近似し、任意の辺上に連続吸着する。

釣り座移動イベントは既存イベントに追加。正規化座標と岸の辺参照、任意の相対角度、保存時のマップ全体のスナップショットを保持する。後日マップを編集・論理削除しても過去イベントは保存時の形で表示する。保存前に形状・特徴物・座標・参照・所属を検証する。利用中マップの削除は確認し論理削除する。

バックアップv12は新テーブルとイベントスナップショットを検証・出力する。RC41データなしの従来形式出力を維持。v12復元はマップを置換し、同IDの異施設・異エリア衝突を拒否。同一バックアップ再取込で重複しない。旧形式復元時は施設に属する独立マップを保持し、イベントは従来どおり置換する。施設情報は既存の統合処理を利用する。形状スナップショットが有効なイベントはマップ参照が失われても再表示可能とする。

## 操作

釣行画面に「エリアマップ管理」と「釣り座を記録」を追加。施設未設定の場合は既存の施設設定へ案内。マップ作成・詳細編集と釣り座の1タップ指定を分離する。既存ネイティブdialogを利用し、背面への画面移動を防ぐ。キャンセルは書込みなし。

メインメニューからも同じ `AreaMapManager` を開けるようにし、施設検索・選択後に事前準備できる。釣行IDは渡さず、施設とエリアに属する独立マップだけを登録・編集する。管理画面を閉じると元の画面へ戻る。ホームの管理モーダルも既存のPWA更新保護の対象とする。

描画はSVG。入力はPointer Eventsでマウス・タッチを共通化。岸タップ／マーカードラッグ、ピンチ拡大、拡大中の移動、明示ズーム・移動ボタンを提供。輪郭編集は詳細モードで行い、自己交差・極小面積・範囲外を拒否する。特徴物は一覧からも選べるので近接配置でも編集可能。元に戻すは編集中ドラフトだけに適用する。

## 日時と将来の釣果関連付け規則

同一釣行の確定時刻イベントだけを対象とし、釣果時刻以下で最新の釣り座を候補とする。同時刻イベントはIDの大きい方を採用する。時刻修正・削除後は都度再計算し、釣果にキャッシュしない。候補の施設・エリアと釣果の確定エリアが異なる場合は関連付けない。別エリア選択時は旧座標を初期コピーしない。近似／不明時刻の記録は確定位置の根拠にしない。RC41では集計・釣果レコードへの保存は行わない。

同じ釣行の直前位置はイベント時刻とIDで選び、新規イベントの初期表示に使用する。過去イベント編集は自身のスナップショットを使用し、現在マップへの置換は明示的なエリア再選択時だけ行う。
