## 1. 目的・最重要条件

ロブルアーのバービー系統について、メーカー公式情報を第一資料、プロショップオオツカの商品情報を補完資料として、**9モデルの製品・カラーをモデル別に登録できるようにする**。手持ちのバービー系を釣果入力時に選択できることを目標とする。ただし**カタログ登録と所有登録は別操作**とし、所有数を勝手に増やさない。

既存のRC21カタログ、釣行・釣果・マイルアー・魚種・タックルの各レコード、ID、参照関係を一切更新・削除・再採番しない。RC19実釣の巾着田 tripId=10 / catchId=11〜14 / T-15・T-18の既存参照を維持。DB v7維持を原則とする。

### WordPress ギャラリーの抽出方法

メーカー公式HTMLの `dl.gallery-item` ごとに、画像リンク／画像のaltと `dd.wp-caption-text.gallery-caption` を対応づけて抽出する。`gallery-1-442` 等の **DOM idを商品コード・カラーコードと解釈しない**。ギャラリー節見出し（F／SS／SSS等）との対応も取る。ページ内でモデル分割が難しいときは保留とする。キャプションの原文と正規化した比較キーを別々に保持し、原文を勝手に変換しない。

`color_class` は `standard / retailer_limited / heroes / 1091 / other_limited / unknown` 等を採用し、確認できないものは `unknown`。限定色を通常色に紛れ込ませない。公式色番号と販売店カラー番号が食い違えば両方記録し、根拠が揃うまで保留。JANとカラー名の1対1対応も無検証では決めつけない。

既存の `docs/rc20/RC20_OFFICIAL_CATALOG.json` はRC20/RC21の出典原本として変更せず、RC22用の**独立差分パック**を作る。ユーザーに渡した過去のExcel・未追跡資料は上書きしない。

## 6. DB登録・UIの要件

1. **事前照合は読み取り専用**。9モデルの各状態を `add_series` / `add_model` / `add_color` / `keep_existing` / `hold_*` に分類、既存ID、色の根拠、保留理由を表示。UTF-8 BOM CSVを保存可能にする。
2. 確認済み商品だけ `productVerified=true` 相当の**明示的な許可リスト**で自動作成可。派生3モデルを無条件で自動登録しない。重量やタイプ・モデル名が曖昧ならモデル単位で保留。
3. モデルごとの色配列と限定区分を保つ。同名カラーでも別モデルは別レコード。別重量への色の流用は禁止。
4. **書き込みは新規シリーズ／モデル／カラーの `add` のみ**。既存メーカー・シリーズ・モデル・色、`myLures`、`catches`、`trips`、`fishSpecies`、タックルを変更・削除しない。
5. 単一のDexie `rw` トランザクション内で再照合し、古いプレビューや競合を拒否。途中失敗は完全ロールバック、繰り返しても追加0（冪等）。DB v7を維持。
6. 所有ルアーの自動追加はしない。カタログ反映後、ユーザーが手持ちのバービーを明示的にマイルアーへ登録する。
7. RC20/RC21の追加ボタンは変更不要ならそのまま機能維持。既存の重複防止ロジックを再利用する。
8. 画面にメーカー公式由来・販売店由来・限定カラー・要確認の区分が分かる情報を出す。ソースが弱い候補を確定扱いにしない。

## 7. 検証・受入条件

### 自動テスト

- build、単体、E2E、PWAオフライン。
- 9モデルを区別、ロングFとロングSS・ガールFとSS・通常F/SS/SSSを混同しない。
- 公式掲載61色の根拠と、実際に確定できた名称の件数を個別に報告。
- 限定色（ヒーローズカラー、1091等）の分類と重複・品番の照合。
- SSS 1.5g（公式）／1.6g（オオツカ）の表記差を別モデルとして重複登録しない。
- 既存RC21 2,218色を含む全既存テーブルについてID・内容変更／削除0、所有4件・釣行5件・釣果7件不変（**試験環境では実機由来のバックアップコピーを使う場合も元端末DBを更新しない**）。
- RC20・RC21再照合で追加0、新規RC22反映後の再照合で追加0。
- プレビューのみ・キャンセルで更新0、競合、再実行、途中失敗の完全ロールバック。

### iPhone実機

- 新版公開・作業前のフルバックアップ取得。RC22事前照合CSVで**実機の予定件数**とIDを確認。
- 反映ボタンはユーザーの確認後のみ。更新後フルバックアップと更新前を比較し、既存全レコード不変・予定したシリーズ／モデル／色だけ増加を確認。
- iPhone Safari PWAで再起動後の表示、圏外起動、釣果へのルアー選択を確認。別環境への復元試験は可能なら実施。
- 実機未検証のまま「実機検証完了」と報告しない。

## 8. Codexへの実装指示・作業境界

`main` を最新化し、既存作業ブランチを確認してからRC22の独立ブランチを使用する。旧未追跡ファイルは保持し、`git add -A` や一括削除はしない。まず**販売店掲載名とモデル名・重量を照合する調査パート**を完了し、9モデルごとに「確定名／未確定名／限定色」の件数表を示す。未確定情報を埋めるために生成名を使わない。

その結果に基づき、確定済みモデル・カラーだけをプレビュー／追加可能にする実装とテスト、上記資料を作成する。**コミット、Push、PR作成、mainへのマージ、本番DB更新はユーザー確認まで行わない。**
