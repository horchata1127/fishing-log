## 登録範囲

調査対象9モデルのうち8モデル・89色を追加候補にし、SSS9行と表記差2行は保留。商品別のカラー配列は独立している。公式掲載61色を追加数と扱わず、公式実名35色・販売店由来の登録候補54色を分ける。詳細なモデル別表と根拠は `RC22_SOURCE_AUDIT.md` に記録。

`src/data/rc22Catalog.ts` と `RC22_CATALOG.json` はRC20/RC21と独立した凍結パック。新規作成は `rc22ModelAllowlist` のモデル名・タイプ・重量に一致し、さらに `productVerified` がtrueの商品だけを許可する。SSSは許可リストから除外。カラー別 `verified=false` の行も追加しない。

## 事前確認と安全性

`src/utils/rc22Catalog.ts` はRC21と同じ正規化・親所属照合・スナップショット比較・単一トランザクションの方式を使用する。メーカーID71を再利用し、メーカー・シリーズ・モデル・カラーの曖昧一致、重量不一致、タイプ不一致、所属違い、タイプ未指定の類似モデルを保留する。公式がタイプを確定した「バービー ロング」の既存別名はF 1.6gとして再利用可能で、SS 1.8gには混同しない。

RC22ではカラー番号だけの一致を採用しない。既存番号と別の名前が衝突したときは新規追加せず対象モデルを保留する。既存カラーの名前・ID・フィールドを修正して対応させる処理はない。

事前確認はDexie `r` のみ。9モデルの状態、色数、`add_series`・`add_model`・`add_color`・`keep_existing`・`hold_*`、既存各ID、公式／販売店出典、通常／限定／区分不明、保留理由を画面とBOM付きUTF-8 CSVで確認できる。キャンセルによるDB更新はない。RC22の確認状態もPWA更新延期判定に含める。

追加ボタンで一つのDexie `rw` を開始し、全カタログを読み直して再照合する。プレビュー後に変更があれば拒否。新規シリーズをトランザクション内で共有し、F/SSが同じシリーズを二重作成しない。失敗時はシリーズ／モデル／カラーをすべてロールバックする。二度目のプレビューは追加0、同じプレビューからの並行適用は片方が成功し、もう片方は古いプレビューとして拒否される。

書き込みは新規シリーズ／モデル／カラーの `add` だけ。モデルにはタイプ、カラーには出典・JAN・原文・限定区分を任意メタデータとして保存する。Dexieインデックス／バージョンを変更せずDB v7を維持。既存レコードにはメタデータを追記しない。従来のバックアップは引き続き使え、新規メタデータもバックアップ書き出し・復元で保持される。

`trips`・`catches`・`myLures`・`fishSpecies`・メーカー・タックルの更新／削除は行わない。所有登録はユーザーがマイルアー画面で明示的に行う。RC20/RC21ボタンと原本は保持する。
