## タイムライン

`TripTimeline.vue`が既存の釣行詳細に表示される。気象パネルがIndexedDBから読んだ時間別データと取得情報を共有するため、グラフ表示・フィルタ・ズーム・タップによるAPI通信は発生しない。明示的な気象取得が完了するとグラフも更新される。

- 時間軸はUTCミリ秒で計算し、ラベルと詳細をAsia/Tokyoで表示。`fishingDate`は変更しない。
- 原則は開始〜終了。終了未記録なら開始と釣果・イベント時刻、開始未記録なら終了と保存記録、両方なければ保存記録の範囲を使う。記録もなければ有効な釣行日のJST一日分を表示し、日時が全くなければ軸を出さない。補完による表示範囲である旨を明示する。
- 時間外の記録も別一覧に保持。別のtripIdのデータは混ぜない。
- 気温は保存済み毎正時の値だけを描画。null・非数・1時間超の欠落で線を切る。実際の0℃は保持。釣果時刻の気温を計算せず、線は直線で結んだモデル推定値と説明する。
- キャッチ・バラシ・放流・ペレットは記録ごとのボタン。色と記号で区別し、44pxの操作領域を確保。同時刻や近接記録は縦の段を増やし、重なりで消さない。
- エリアフィルタは釣果・バラシのみ。エリアIDを優先し、IDがない旧記録は保存snapshotを用いる。特定エリア選択時も未設定を初期状態で含め、チェック解除と未設定だけの選択も可能。気象・イベントと軸の範囲は変えない。
- 追加依存なし。SVGとネイティブボタン・dialog、ResizeObserver、1/2/4倍の内部横スクロールを使用。PWAの静的precacheと既存更新方式を維持する。

## イベント時刻の制約

現行`TripEvent`とバックアップは`occurredAt: Date`必須で、時刻不明を新規登録する契約はない。本PRでその保存仕様・記録ボタン・既存時刻を変更しない。

表示モデルは将来の読み取りにも備え、欠損・無効時刻、または`timePrecision: unknown`を時間軸外の「時刻不明イベント」に表示する。`approximate`がある場合は「約」と破線で区別する。保存時刻から精度を推測しない。未知精度の作成・編集を将来追加する場合は、DB型・バックアップ検証・復元・既存の時刻修正UIをまとめて拡張する必要がある。

2026-10-17の日本イワナセンターのペレット散布について、正確な時刻も新規イベントも作らない。時刻不明・概算のE2Eは別の合成釣行の使い捨てDBでのみ再現する。

## 手動座標の再利用

1. 地点未保存の釣行の「気象データ」を開く。
2. 同じfacilityIdの、開始日時がより古い釣行に保存されたmanual/WGS84地点だけを候補に表示する。釣行と地点双方のfacilityIdを確認し、名称だけでは一致判定しない。
3. 異なる座標が複数なら警告と選択肢を表示。同じ座標の候補はまとめ、利用釣行数と最も新しい保存元を示す。
4. 候補を選んでも入力・DB・通信は変化しない。「選択した地点をこの釣行に保存」を押すと保存する。
5. API取得は既存の「過去の気象データを取得」を別途押す。圏外でも候補の表示・確認保存と保存済みグラフの閲覧は可能。

保存時のトランザクションで、保存元の座標・更新日時・開始日時・施設ID、保存先の施設IDと未保存状態を再検査する。変更や競合があれば拒否し、既存地点を保持する。地点の保存方式は明示選択による`manual`のままで、新たな由来フィールドは追加しない。

## 気象出典

共有`WeatherAttribution.vue`を再利用し、Open-Meteo Historical Weather API（Best Match）のモデル推定値、現地実測ではない旨、Open-MeteoとCC BY 4.0のリンクをグラフにも表示する。

使用した取得リクエストの手動地点とモデル格子点・標高・取得期間・取得時刻を確認できる。現在の地点と取得地点が異なる場合も明示し、元のメタデータと出典・ライセンスURLを保持する。予報API、Historical Forecast、アメダスの取得は追加しない。既存の非商用API利用に関する案内も維持する。

## iPhone実機での確認手順（レビュー環境）

本番バックアップの復元や実機IndexedDBの削除はしない。専用の検証用origin・合成記録を使う。

1. Safariとホーム画面PWAの両方で釣行詳細を開く。全体幅が収まり、凡例・JST時刻・44pxマーカーが読めることを確認。
2. 近接した釣果をそれぞれタップし、時刻・ルアー・魚種・施設／エリアsnapshotと閉じる操作を確認。
3. 2/4倍で内部だけ横スクロールし、1倍に戻す。エリアを選び、未設定記録の含有切替と気温・イベントの不変を確認。
4. 保存済み気象がない合成釣行でも記録だけを閲覧。欠損値のところで線が切れることを確認。
5. 同じ登録施設の新しい合成釣行で地点候補を選択。保存前に地点が未保存、確認保存後もAPI取得は始まらないことを確認。
6. PWAの「圏外利用の準備完了」を確認し、機内モードにしてアプリを完全終了・再起動。グラフ、詳細、候補選択と保存地点が使えることを確認。
