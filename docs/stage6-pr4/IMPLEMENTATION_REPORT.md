## 採用方式

指示書で許可された「承認後に有効化する静的正式配布フロー」を採用した。任意JSONをユーザーがドラフトから正式版へ昇格するUIは設けず、既存の施設選択UIをそのまま再利用する。

`src/data/stage6FacilityRelease.ts` は `status: pending` に固定。候補は `docs/stage6-pr4/facility-master.candidate.json` に隔離し、runtime/publicから参照しない。通常起動では施設DBの読み書きを行わず、50施設はまだ自動配布されない。候補の `full` は正式スキーマを検証するための派生表現であり、内容承認・配布許可ではない。元ドラフトは `research-source.json` にバイト一致で保持する。

承認後は別のレビュー可能な変更で、承認済みJSONをアプリの静的依存へ移し、レジストリを `approved` に設定する必要がある。このPRのマージだけでは有効にならない。環境変数、URLパラメータ、ブラウザ内のチェックボックスでは承認ゲートを解除できない。

`initializeFacilityRelease` は承認済み配布のみを既存 `applyFacilityMaster` に渡す。PR1の `validateFacilityMaster`、canonical生成、`planFacilityMasterUpdate`、PR2の3ストア原子的適用、版競合、退役、user行保持を変更しない。起動適用が失敗すれば理由を表示して既存釣行の読込みを継続する。初期化中はアプリ操作とPWA更新を保留する。

## データと互換性

生成スクリプトは原本と73エリア入力を読み取り専用で比較し、想定外の差分を拒否する。候補は正式フィールドの明示選択で生成し、調査フィールドは原本・監査JSONに残す。唯一の実データ修正はキングフィッシャー5号池のsortOrder 1→5。全ID・名称・日付・営業状態を保持し、確認状態を昇格しない。

DB v7、バックアップv6、旧v1〜v5復元、PWA/SW設定、既存カタログ・タックル・釣果保存処理に変更なし。適用は公式施設・エリア・metadataだけを対象とする。同名user施設と公式施設は別IDで共存し、既存UIの「公式」「ユーザー登録」で選択を区別する。既存自由入力釣行への自動紐付けやsnapshot更新は行わない。

候補を将来静的同梱する場合、初回のアプリ取得とSWキャッシュ準備にはネットワークが必要。その後の適用・施設検索・釣行/キャッチ/バラシ保存にはネットワーク不要。このPRでは候補を同梱せず、隔離テストだけに投入した。オフライン試験のv6復元はテスト準備専用であり、本番のマスター導入手順ではない。
