# RC33 購入品・カラーマスター追加

作業日: 2026-11-01 / ブランチ: `codex/rc33-purchased-lures-colors`

## 使い方と適用範囲

ホームのルアーマスターで「RC33 購入品・カラーの追加予定を確認」を押すと、端末の既存カタログ・所有・配色と照合する。「RC33の確認済みデータを追加」で適用直前のバックアップをダウンロードし、カタログ・所有・配色を単一トランザクションで追加する。確認・キャンセルは読み取りのみ。起動・復元による自動適用はない。

今回の端末接続・実ユーザーDBへの適用は行っていない。購入11個の登録はこの操作で利用端末に反映できる。資料バックアップは読み取り専用で調べ、プロセス内のfake-indexeddbで適用・復元検証を実施した。

## 実装・安全性

- RC31の明示的な差分登録方式に沿い、RC33もメーカー→シリーズ→モデル→カラーの順にDB採番する。新規メーカーの共同ブランドは作らず、ルランは既存の「ロブルアー」に所属。共同開発元は資料・出典に残す。
- モデルはメーカー・シリーズ・名称／別名・重量・全長を照合。別シリーズの同名モデル、親の複数一致、コードと名称の競合、配色参照の不一致は対象モデルを保留する。
- カラーはモデル内のコードを優先し、コード未登録なら元名称・表示名・別名を照合。コード比較時だけ数字のゼロ埋め、NFKC、空白・ハイフン差を吸収する。元データを更新しない。
- くるんはサーキットボードの回転系ルアーなのでカタログカテゴリは「その他」。配色レイアウトには表裏を表せる既存の`spoon`を使い、写真に写った面を`front`に記録。裏面は未確認のため未設定。モデルは45mm/1.1g。Type2は追加しない。
- Pepinoは既存56mm/2.6gのDR-SSを使う。共通カラーチャートの形状や目玉は配色データへ転記しない。写真で確認できた側面だけを登録。縞模様は現行辞書に対応パターンがないため無理に別パターンへ置換しない。
- PALMSのMT-933は既存IDを維持。名称だけで茶一色と推定せず、公式画像の茶系の背・青紫系の側面と斑点を既存パレットで近似。
- 公式画像の配色は`origin=photo, confirmed=true, userEdited=false`。検索用の48色への近似であり測色値ではない。`evidence.sourceUrl`には画像URL、`basis`には観察範囲と制限を保存。辞書では「公式画像・確認済み」と出典を表示する。確信度が未設定なら0%と表示しない。
- 公式画像を確認していない色はRC32の名称推定器だけを使い、`origin=name, confirmed=false`として参照URL・根拠・推定器版を残す。名称にないラメ・メタリック等を付けない。
- 既存配色は推定済みを含め一切上書きしない。手動編集・確認済み・参照解除済みプロフィールも保護。参照解除済みとの衝突は自動再リンクしない。
- 所有は1レコードが1個。購入対象と同じvariantIdの既存所有があれば非アクティブ・未確認を含め追加しない。その状態を変更せず、プレビューに「既存所有保持」と表示する。その他の追加カラーは所有登録しない。
- プレビュー照合トークンはカタログ4表・所有・配色を含む。別画面から変更されたら再確認を要求し、古いプレビューでは一切追加しない。途中の失敗はカタログ・所有・配色をまとめてロールバック。
- Dexie v9・バックアップv8は変更なし。`catalogEvidence.revision`の型にRC33を追加しただけで、新ストア・索引・スキーマ移行・起動シードは追加していない。既存JSONの編集・初期化・全件削除は取り込み処理にない。

## バックアップ互換性

v7資料から取り込んだ隔離DBにRC33を適用し、v8で出力→既存`importBackup`で復元→全テーブル一致を確認。既存v7復元規約（配色の自然キーを保持し、端末IDを安全に解除）は変更していない。古いバックアップ復元後に配色参照が解除された場合は保留し、手動確認なしの自動再リンク・二重追加をしない。

再現コマンド（実バックアップのパスはローカル専用）:

```powershell
node scripts/audit-rc33.mjs docs/rc32/fishing-log-backup-2026-10-31.json
```

このスクリプトの出力は集計と製品候補だけで、釣行・釣果・所有の個別内容や実バックアップ本体は書き出さない。

## 釣行画面の調査

`CatchModal.vue`の所有・カタログ候補と最近のルアーには既存のSVGプレビューがある。`FishingScreen.vue`の釣果履歴にも、釣果保存時の`visualColorSnapshot`があれば表示される。今回の配色は同じ既存構造を使うため選択時に反映され、逆引き・所有絞り込み・SVG表示を利用できる。

不足箇所: 釣行中の「現在の設定」のルアー欄と`TripTimeline.vue`の時系列はカラー名中心でSVG表示がない。過去の釣果に配色snapshotがない場合も後付け表示はしない。履歴の配色を現在の辞書で置換しないための既存動作を維持した。これらへのアイコン追加は今回の調査結果として残す。

## 残課題

- WAHとルランの公式カラー画像による配色確定。メーカー製品一覧ではルランの個別ページが見つからず、販売店でモデルと10色を照合した。
- くるん裏面、Pepinoの不可視面、縞模様の専用表現、限定色の発光状態は未確定。
- 一部HERO'S番号は販売店の選択肢番号でありメーカー公式コードと断定できないため空欄。茶目・赤目はCSVの別名に残すが、眼の仕様は確定登録しない。
- 実ユーザー端末への適用とiPhone Safari実機での確認は未実施。ローカル隔離検証の件数と端末の追加件数は異なる場合がある。
- ビルドの500kB超チャンク警告は既存の構成に由来し、コード分割は今回の対象外。
