# 魚種マスター原本と変換

正式原本はリポジトリ外の`C:\Users\plain\source\fishing-log-notes\fishing-log-fish-master-reviewed-2026-10-10.xlsx`（ユーザー指定の移動先）。
`fishMaster.ts`は`scripts/convert-fish-master.py`で読み取り専用変換したデータです。ファイル名・SHA-256と4シートの全データを保持しています。原本を変更したり、名称・分類・確認状態を推測で補完したりしません。

```powershell
python scripts/convert-fish-master.py
```

Python標準ライブラリのZIP/XML読み取りを使用します。原本がなければ停止します。ヘッダー、44件、安定ID、37件の内訳と名称重複を検証してから出力します。

| 原本シート | データ行数 |
| --- | ---: |

| ブランド放流確認 | 28 |
| 保留・対象外 | 18 |

`fish_id`、`group`、`display_name`、`aliases`、`region`、`lineage_or_type`、`source_status`、`notes`、`source_url`を文字列のまま保持します。空セルは空文字列。Excelのふりがな・書式は表示文字列へ混ぜません。別名やURLの原本表記を勝手に分割・正規化しません。

初期登録はニジマス1件＋イロモノ15件＋`source_status = 管釣り実績確認`のブランドマス21件＝37件です。
イロモノの`二次資料確認`もそのまま保持します。ブランドの対象外7件（F017・F018・F019・F021・F023・F024・F025）と他シートは調査資料として残し、初期登録には使用しません。

## 保存と再シード

- DB v6で`fishSpecies`を追加し、Excelの文字列`fish_id`を主キーとします。
- 起動・マイグレーション時に初期シードや既存釣果への魚種割り当てを行いません。
- 管理画面の「初期魚種37件を登録」で明示登録します。
- 新規釣果入力では不足する初期候補をメモリ上に提示します。選択・キャンセルだけでは書き込みません。
- 未登録初期候補を使う記録の保存時は、不足する初期魚種・カタログから特定したルアーの所有登録・記録を同一トランザクションで保存します。失敗時は全部ロールバックします。キャッチ・バラシとも既存の実所有があれば再利用し、なければ所有個体を1件だけ自動登録します。手入力だけでは所有を作成せず、記録の編集・削除で所有を自動削除しません。
- 同じIDまたは登録済みの同名候補を上書き・重複登録しません。ユーザー編集、非表示、追加レコードを保持します。
- ユーザー魚種は`user:<UUID>`。`origin`と`userEdited`で原本・追加・編集を区別します。
- 新規釣果はF001が有効ならニジマス初期選択、非表示なら未設定。過去の釣果には補完しません。
- 選択保存では`fishSpeciesId`、`fishSpecies`（名称）、`fishSpeciesGroup`（分類）のスナップショットを保持します。
- 「前回と同じ」は保存済みのID・名称・分類を引き継ぎます。非表示の過去魚種も引き継げますが、通常候補には表示しません。全長`fishSizeCm`はコピーしません。

## バックアップ

魚種データがある場合はv5・全13テーブル。未導入データは従来のv2/v3/v4出力を維持します。旧v1〜v4は魚種テーブルなしでも復元できます。

旧13テーブルの復元は従来同様の置換です。現在のユーザー追加・編集魚種を部分マージせず、バックアップの状態へ置き換えます。旧形式の復元後は魚種テーブルが空になりますが、メモリ上の37候補は選択可能で、明示登録または選択保存で再シードできます。過去釣果へニジマスを割り当てません。

施設・エリア・適用metadataまたは場所参照がある場合はv6・全16テーブルを書き出します。新データがなければ従来のv2〜v5出力を維持します。v1〜v5の復元では端末の新3テーブルを保持し、v6ではユーザー施設・エリアを非破壊mergeします。同IDで異なる内容は全復元を拒否します。公式マスターはreleaseOrderを巻き戻さず、過去参照に必要な公式行は退役として保持します。旧13テーブルの置換と新3テーブルのmergeは単一トランザクションです。
